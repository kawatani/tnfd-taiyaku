# 対訳データ作成仕様

ソースはすべて TNFD が CC BY 4.0 で公開している文書（`sources/`）。ページ単位のテキストは `work/pages/<doc>/NNN.txt`（NNN = PDFのページ番号、3桁ゼロ埋め）。

- `rec`    … Recommendations of the TNFD (September 2023, 英語)
- `rec_ja` … 自然関連財務情報開示タスクフォースの提言（TNFD 公式日本語版）
- `leap`   … Guidance on the identification and assessment of nature-related issues: The TNFD LEAP approach (Version 1.1, October 2023, 英語)
- `leap_ja` … 自然関連課題の特定と評価に関するガイダンス：TNFD LEAP アプローチ（第1.1版、TNFD 公式日本語版）
- `tc`     … Additional sector guidance – Technology and communications (September 2026, 英語)

## 出力形式

担当範囲ごとに 1 ファイル、`work/aligned/<doc>-<AAA>-<BBB>.json`（AAA/BBB は英語版の開始・終了ページ、3桁ゼロ埋め）。UTF-8、次の形：

```json
{
  "doc": "rec",
  "pages": [21, 40],
  "segments": [
    { "page": 21, "type": "h2", "en": "2.1. Nature-related issues", "ja": "2.1. 自然関連課題" },
    { "page": 21, "type": "p",  "en": "…", "ja": "…" }
  ]
}
```

- `page` … その段落が始まる **英語版 PDF のページ番号**（整数）。
- `type` … 次のいずれか：
  - `h1` 章（例: "3. Recommendations and guidance"）、`h2` 節（"3.1."）、`h3` 項（"3.1.1." や小見出し）、`h4` さらに下位の小見出し
  - `p` 本文段落
  - `li` 箇条書き・番号付きリストの 1 項目（先頭の記号 • は除く。番号や (a) などは残す）
  - `quote` 引用・囲み記事（コラム）の本文
  - `caption` 図表のタイトル（"Figure 3: …", "Table 2: …"）
  - `figure` 図・インフォグラフィック内の短いラベル群をまとめたもの（意味の通る範囲で 1〜数セグメントに要約的に並べる。断片的な数字だけのものは省略可）
  - `table` 表。`en`/`ja` には **パイプ区切りの Markdown 表**（1行目ヘッダ、2行目 `|---|---|`）を入れる。セル内の改行は `<br>` で表す。大きな表は行のまとまりごとに複数の `table` セグメントに分けてよい（ヘッダ行はそれぞれに付ける）
  - `footnote` 脚注（`en` の先頭に番号、例 "14 IPBES (2019) …"）
- `flag`（任意）… 問題がある場合のみ短い英語メモ。例 `"no-ja-match"`, `"ja-split-differs"`, `"layout-uncertain"`。

## 共通ルール

1. **ランニングヘッダ・フッタを除去**：文書名＋"September 2023"/"2023 年 9 月"/"September 2026"、単独のページ番号、"tnfd.global" など。
2. **段落を正しく復元**：PDF 由来の改行・ハイフネーション（"organi- sations"）を直し、ページや段組をまたいで分断された段落は 1 つにつなぐ。段組の読み順が崩れている場合は文脈から正しい順に並べ直す。
3. **担当範囲の境界**：英語版の担当ページ [AAA, BBB] で **始まる** 段落だけを出力する。AAA ページ冒頭が前ページからの続きの文なら出力しない（前の担当者が出す）。BBB ページ末尾で始まり次ページへ続く段落は、次ページを読んで最後まで完結させて出力する。
4. 本文の内容は省略しない（要約しない）。目次ページは `h1` 1つ（"Contents"/"目次"）だけにして中身は省略してよい。
5. 文字列内の改行は使わない。例外は `table` で、表の行の区切りには改行（JSON上は `\n`）を使い、セル内の改行は `<br>` で表す。JSON として正しくエスケープすること。書き出し後に `node -e "JSON.parse(require('fs').readFileSync(process.argv[1],'utf8'))" <file>` で検証する。

## rec（提言）・leap（LEAPガイダンス）の対訳：公式日本語版を使う

`leap` では `rec_ja` を `leap_ja` に読み替える。

- `ja` には **TNFD 公式日本語版の文言をそのまま** 入れる。自分で訳し直したり、言い回しを改善したりしない。
- 許される修正は PDF 抽出に起因するものだけ：日本語文字間の不要な空白の除去（"自 然 関 連 の リ ス ク" → "自然関連のリスク"、"支持 し" → "支持し"）、改行の除去、段組崩れによる順序の復元。英数字と日本語の間の半角空白（"TNFD の"）も除去してよい。
- 日本語版のページは英語版とほぼ同じだが、後半で 1〜2 ページずれる。担当範囲の前後 3 ページまで日本語版を参照して対応箇所を探す。
- 英語の 1 段落が日本語では 2 段落に分かれている等、分け方が異なる場合は **英語側の区切りに合わせて** 日本語を結合・分割する。
- 対応する日本語が見つからない場合は `ja: ""`、`flag: "no-ja-match"`。

## tc（技術・通信ガイダンス）：新規翻訳

- `ja` は英語原文の **忠実な全訳**（省略・要約・意訳による加筆をしない）。
- 文体は公式日本語版提言にそろえて「である調」。
- 用語は `work/glossary.md` に従う（TNFD 公式日本語版の訳語）。そこにない用語は一般的・公的な定訳を使い、必要に応じて初出時に原語を括弧で併記してよい（例：ファブ（半導体製造工場））。
- SICS® のコード（TC-SC など）、指標番号（C1.0、TC-SC-140a.1 など）、固有名詞の略語（LEAP、ISSB、GRI、ESRS、SBTN など）は原文のまま残す。組織名は定訳があれば日本語、なければ英語のまま。
- 単位・数値・脚注番号は原文どおり。
